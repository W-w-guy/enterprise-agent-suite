# 企业 Agent 系统 · 四个切片的可运行实现

这是 [客户代发] 系列订单 43/50、34/50、19/50、44/50 四个切片的交付件。
不是方案文档，是能跑、能被你复核的代码。

## 为什么合成一个包

四单本来就是同一个「企业知识库与多 Agent 协作系统」的拆分需求。
拆成四个互不相干的小脚本，你以后要把它们接起来还得再写一遍胶水；
所以这里给一份共享内核 + 四个切片，各自独立可跑，也能一起跑。

    core/          共享内核：原子写、追加式台账、审批硬门、金额、证据引用、文本清洗
    slices/        四个切片，每个都能单独当命令行工具用
    data/          脱敏样例数据（不是真实客户数据）
    tests/         109 项测试
    tools/         打包、自检、清单

## 一条命令跑通

    python3 run.py demo

Python 3.9+，零第三方依赖（纯标准库），不联网、不需要任何账号或密钥。
输出落在你指定的目录，两次运行产物字节完全相同。

## 四件事你在验收时能自己确认

1. **审批没过，东西出不去。** 未审批直接投递会被拒；审批之后正文改一个字节，
   审批记录立刻失效并留痕。测试：`tests/test_slices.py::S1531Test`。
2. **脏数据不会让整批停摆。** 一行坏数据进「被拒」清单（带行号），好行照常处理。
   历史教训是 1000 行表里 1 行缺字段把整个日常流程卡死。
3. **同样的输入，同样的字节。** demo 跑两遍，7 个产物的 SHA256 完全相同；
   换机器也一样（金额用整数微美元算，不用浮点）。
4. **每条结论都能指回来源。** 知识图谱里没有引文的边不入图；
   经营数据里没登记口径的指标不分析；数据不齐时不给建议。

另外三件只有真跑过才知道要做的事（都已做）：
- 中文 Windows 上另存为 GBK 的 JSON/CSV 能读（依次试 utf-8-sig / utf-8 / gb18030）。
- 批文人必须是**当前**责任人；换了人，旧批文立刻失效。
- 通知正文超过队列上限时，在入队前就拦住，不让你去队列日志里找原因。

## 自检

    python3 tools/verify.py

4 项：109 项测试、demo 字节一致、MANIFEST 哈希逐个核对、产物不含本机路径。

## 边界（写在前面，免得后面扯皮）

- 不含任何真实账号、密钥、客户数据。样例数据全部虚构。
- 不连接真实的飞书 / WPS / 模型 API；连接器给的是可替换 transport 的骨架 + 真实差异建模。
- 不含云资源与模型 API 费用。
- 不承诺「做了就一定能提升指标」。看板只负责把差异算准并说明样本够不够。
