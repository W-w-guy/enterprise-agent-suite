# 34/50 知识图谱子域

## 客户原话要什么
「在高价值业务子域建立实体、关系与证据引用。」

## 交付形态
`python3 run.py 1521 kg <三元组.csv> <文档表.csv> <中心实体> <输出目录>`

输入三元组每行必须带 `doc_id` 与 `quote`（原文引文）。

## 核心口径：没有证据的边不进图

知识图谱在客户那边最容易失信的地方，是「它说有」。所以：

| 情况 | 处理 |
|---|---|
| 有引文、文档存在 | 入图，边上带 doc_id + quote |
| 有文档但缺引文 | **不入图**，进「未入图」清单，说明要补哪句原文 |
| 文档不存在 | **不入图**，进「未入图」，指出是哪个 doc_id 缺失 |
| 谓语不在白名单 | 拒绝，进「被拒」，要求人工改 |
| 主语=宾语 | 拒绝（自环没有信息量，通常是把关系写反） |

输出里每条边都印出证据：`订单系统 —依赖→ 库存服务　证据：doc_arch「下单需调用库存服务预占」`

## 子图查询
`subgraph(center, depth)` 支持 1–N 跳，输出节点集与边集。中心实体不在图中时明确报错，不返回空图假装成功。

## 对抗轮补的三类检测（只报，不自动改）

| 场景 | 处理 |
|---|---|
| 订单系统 / 订单系统(OMS) / OMS | 报「疑似别名」，**不自动合并** —— 合并错了比不合并更难查 |
| 引文里宾语出现在主语之前 | 报「疑似主宾写反」 |
| 依赖成环 A→B→C→A | 报出环路径 |

## 边界
不内置分词与实体识别（那需要领域词典与样本），本切片处理的是「已抽好的三元组」如何变成可信子图。
