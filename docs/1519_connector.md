# 32/50 飞书与 WPS 连接器

## 客户原话要什么
「实现授权文档同步接口，保留来源和权限映射。」

## 交付形态
`python3 run.py 1519 sync <远程文档.json> <输出目录>`

四步固定：拉取 → 权限映射 → 幂等 upsert → 落来源戳。
换真实 API 只换 transport，不改这四步。

## 两家 API 的真实差异（mock 按差异建模，不是随意捏）

| | 飞书 | WPS |
|---|---|---|
| 分页 | `page_token` | `offset + limit` |
| 权限 | openid + 部门/群组 | 角色码 + 显式 ACL |
| 限流 | 429 + `Retry-After` | 500 抖动，无 `Retry-After` |

## 三条硬规则

1. **映射不上的权限一律不给。** `R9`（未知角色）不进 `roles`，进 `unmapped_principals` 并留痕。
   宁可少同步一篇，不能多给一次权限。
2. **瞬时故障重试，403 立刻停。** 429/500 重试 3 次；403 是授权失效，重试没意义，
   停止并保留游标，等人工重新授权。
3. **幂等 + 来源戳。** 同一 `(provider, doc_id, rev)` 第二次跑 upsert 数为 0；
   每条记录带 `provenance.source/endpoint/cursor` 与内容 sha256。

## 对抗轮补的两件事

| 场景 | 旧行为 | 现行为 |
|---|---|---|
| 权限被收回（v2 少了 finance） | 只写一条 upsert | 加 `permission_revoked` 事件，能回答「谁何时失去访问权」 |
| 同一内容在飞书与 WPS 各一份 | 当成两条独立文档 | 报「跨平台同内容」，要求人工确认权限以哪边为准（不自动合并，合并会丢来源） |

## 边界（务必看）
**本包不含真实飞书/WPS 凭证，也没有对接真实开放平台。**
给的是：可替换 transport 的骨架、两家分页/权限/限流差异的建模、以及可复跑的 mock。
接真实平台需要客户提供企业资质与应用授权，属另行约定范围。
